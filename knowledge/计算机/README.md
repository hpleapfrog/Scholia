# 计算机

> **English: [README.en.md](README.en.md)**

> [!IMPORTANT]
> **本学科收「标准与官方文档规定了什么」，不收「一步步怎么做」。**
>
> 教程、安装步骤、排错流程到处都是，重复它们只是噪音——**稀缺性判据**。
> 而**某个协议字段的取值语义、某个 API 的默认行为、某项兼容规则的适用条件**，
> 只有翻回标准或官方文档原文才拿得准，转述常常已经过期或走样。

**十四条全部出自 IETF 的公开 RFC 与 IANA 的公开注册表**（`ev-052` / `ev-053` / `ev-054` / `ev-057`，核验深度见各自条目）。这意味着本学科目前的覆盖面
**不等于**「计算机」这个学科本身——见下节「还缺什么」。

### 还缺什么

| 缺口 | 为什么重要 | 需要的来源 |
|---|---|---|
| **RFC 9110 §15.2–§15.6 其余各具体码** | `204`、`304`、`401`、`403`、`405`、`410`、`503` 已核（`ev-054`），注册表也已核（`ev-057`），但**其余具体码在规范里的定义一个都没核**：`418` 那段说明的完整上下文、`413`/`422` 在 RFC 9110 里改没改名、`301`/`302`/`303` 对方法改变的规定，本库都只读了转述 | RFC 9110 §15.2–§15.6（已在 `ev-054` 内，只是未核） |
| **RFC 8126 §4.8 对 IETF Review 的具体定义** | §16.2 已核（`ev-054`），但那一节只写了「require IETF Review」并指向 RFC 8126，**RFC 8126 §4.8 本身没读**——「IETF Review 具体意味着什么门槛」仍然答不了 | RFC 8126 §4.8（需新证据） |
| **语言与平台的官方文档** | 现有十二条全是网络协议；「某个 API 的默认行为、某项兼容规则」一条都没有 | Python / Java 等官方文档，带版本号与发布日期 |
| **格式与编码规范** | `JSON` / `UTF-8` / `HTML` 这类格式的**约束与默认值**，转述最常出错 | RFC 8259 · Unicode 标准 · WHATWG 标准 |
| **版本差异条目** | 「X 在 v1 与 v2 之间改了什么」是本学科最典型的可核对内容，目前为零 | 各规范的版本沿革页 |

**本学科的下一条目应该优先补其余具体码**——`204`、`304`、`401`、`403`、`405`、`410`、`503` 已核（`ev-054`），
注册表也已核（`ev-057`），但**其余具体码在规范里的定义一个都没核**。
`ev-054` 已登记，**不需要新证据**。




## 边界

| | 收 | 不收 |
|---|---|---|
| 内容 | 协议与格式规范、语言与平台的官方文档中**可定位**的定义、默认值、约束、版本差异 | 教程、命令序列、配置步骤、最佳实践清单 |
| 出处 | 标准组织或厂商的**正式文档**，带编号 / 版本 / 发布日期 | 博客、问答、二手总结 |
| 表述 | 「文档 N 规定了 X（编号 · 版本 · 待核对）」 | 「推荐做法是 X」 |

**只收公开可查的文档。** 需要付费订阅才能读到的规范，本库无法核验，不登记为证据。

### 与相邻学科的分界

| 学科 | 它回答什么 |
|---|---|
| **计算机** | 规范**规定**了什么：字段、默认值、约束、兼容性 |
| [科学](../科学/README.md) | 教材与出版物中的勘误：印刷出来的东西哪里错了 |

两条判据同样是**稀缺性**与**风险**：会出事的流程不装（见
[决策记录：程序性知识的边界](../../docs/decisions/procedural-knowledge-boundary.md)），
教程不重复。**本库不教怎么写代码，只记规格里写着什么。**
