## 陈述

**405（Method Not Allowed）响应必须带 `Allow` 头部，且必须列出目标资源当前支持的方法。**

RFC 9110 §15.5.6 原文（短引用）：

> The origin server **MUST** generate an **Allow** header field in a 405 response
> containing a list of the target resource's currently supported methods.

同节还规定了缓存行为（短引用）：

> A 405 response is **heuristically cacheable**; i.e., unless otherwise
> indicated by the method definition or explicit cache controls (see
> Section 4.2.2 of [CACHING]).

### 405 与 501 的分工

§15.5.6 把 405 定义为「**源服务器认识这个方法，但目标资源不支持**」；
§15.6.2 把 501 定义为「**源服务器不认识这个方法**」。
两者都涉及"方法不被接受"，但**责任方不同**——405 指向资源，501 指向服务器。

## 论证

### A1 · `Allow` 头部是 MUST 级要求，不是建议（尚无攻击）

- **主张**：源服务器在生成 405 响应时，**必须**生成 `Allow` 头部，
  且该头部**必须包含目标资源当前支持的方法列表**
- **前提**：§15.5.6 明写 "The origin server **MUST** generate an **Allow** header field"（ev-054）
- **推理**：
  1. 这属于「**标准与官方文档规定了什么**」——正是[计算机](../README.md)学科收的东西
  2. **MUST 是 RFC 2119 里的最高强度词**（见
     [RFC 里的 MUST / SHOULD / MAY 只在全大写时才有规范含义](RFC要求关键词只有全大写才成立.md)）——
     这不是"建议带上"，而是"不带上就是违反规范"
  3. 实际后果：**很多服务端返回 405 时不带 `Allow`**，
     于是客户端**无从得知该资源到底支持哪些方法**——这是实现违反规范，
     不是规范允许省略
- **证据**：ev-054
- **被攻击**：见 A2

### A2 · 本条不保证任何具体实现遵守该 MUST（尚无攻击）

- **主张**：本条陈述的是**规范要求 405 响应带 `Allow`**，
  **不陈述「任何具体服务端都带了 `Allow`」**
- **前提**：§15.5.6 用 MUST 写了要求（ev-054），但**本条没有实测任何服务端**
- **推理**：
  1. 规范的 MUST 与实现的遵守是两回事——**本库没有实现测试的机制**
  2. 同理，「405 默认可缓存」是规范的默认值，**不是实现的义务**——
     与 [204 默认可缓存](HTTP204响应不能含正文也不能含trailer且默认可缓存.md) 是同一类情况
  3. 所以本条**不能被用来主张「我收到的 405 响应缺 Allow 头部是正常的」**
- **证据**：ev-054
- **被攻击**：**本条只陈述 RFC 9110 §15.5.6 的原文，不保证任何具体服务端的行为。**
  「默认可缓存」是规范的默认值，不是实现的义务。
  另外：**本条未核对旧版 RFC（7230–7235）对 405 的表述**——
  旧版是否也写了同样的 MUST，本库不知道。
- **署名**：@hpleapfrog · 2026-10-12
- **待补**：RFC 7230–7235 对 405 的表述；主流服务端 405 响应带 `Allow` 的实测

## 为什么这条算「真实信息」而不是「噪音」

> [!IMPORTANT]
> **任何一篇 HTTP 教程都会告诉你「405 表示方法不被允许」，但不会告诉你规范用 MUST 要求响应必须带 `Allow` 头部。**
>
> 后者是规范里的一句话，转述里几乎见不到：
> **它决定了一个 405 响应是不是"完整"的——缺了 `Allow`，客户端就无从得知该用哪个方法重试。**
>
> **本库的使命是「去除噪音、存放真实信息」。**
> 「405 表示方法不被允许」是噪音——教程都在讲；
> 「405 必须带 `Allow` 头部，且必须列出支持的方法」——这条藏在 RFC 9110 §15.5.6 的一句 MUST 里，
> **才是本库该装的。**
