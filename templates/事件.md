# 事件 模板

> `事件` **不是第七种对象类型**，而是与 `objects` 并列的另一类记录：
> 它回答「**发生了什么**」，只有证据，**没有可被攻击的主张**。
>
> 因此它单开顶层 `events/`、**不进** `knowledge/`、**没有 `## 论证`**、**没有任何边**。
>
> 跑 `python tools/new_entry.py --type 事件 --slug your-slug --title "你的标题"`。

```markdown
---
id: {{ID}}
type: 事件
title: {{TITLE}}
status: 持续更新
author: "{{AUTHOR}}"
created: {{DATE}}
updated: {{DATE}}
evidence: [{{EVIDENCE}}]
license: CC-BY-SA-4.0
---

## 陈述

**按时间把事情说清楚**：谁、在什么时候、发布了什么、范围多大。

| 日期 | 发生了什么 | 谁说的 |
|---|---|---|
| | | |

## 依据

| 编号 | 类型 | 等级 | 定位 | 许可 |
|---|---|---|---|---|
| {{EVIDENCE}} | 官方文件 / 指南 | 高 | | |

> [!IMPORTANT]
> **事件不带任何结论。** 不要写「这说明……」「因此应该……」——
> 那是一个**命题**要做的事，而命题需要论证、需要能被攻击。
> 把事件写成命题，会逼出一堆**没有攻击点的假论证**。

## 变更记录

| 日期 | 操作 | 依据 | 谁 |
|---|---|---|---|
| {{DATE}} | 建立事件索引 | {{EVIDENCE}} | {{AUTHOR}} |
```

## 这个类型最容易写错的地方

| 错法 | 后果 |
|---|---|
| 加了 `## 论证` 或 `edges` | 校验器失败（`R-EVENT-01`）：事件没有真值可攻 |
| 用 `已确证` / `争议` | 校验器失败：事件状态只有 **持续更新** / **已封存** |
| `evidence` 为空 | 校验器失败：**证据为空等于没有事件** |
| 忘了登记 `events/README.md` | 校验器失败（`check_event_readme`） |
