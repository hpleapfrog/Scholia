# 缺口看板：四张嘴，一个脑子

> **English → [gap-dashboard.en.md](gap-dashboard.en.md)**

> 定于 **2026-10-30**。页面本身在 [`docs/GAPS.md`](../GAPS.md)；这里记**为什么**。

## 原来的样子

「这个库还缺什么」有四个出口，各自算各自的：

| 出口 | 原来怎么算 |
|---|---|
| `tools/make_tasks.py` | 自己扫 README、自己数「待审」、自己判断「缺教法」 |
| `docs/GAPS.md` | **不存在**——想知道全貌要读 500 行 `make_tasks` 的输出 |
| MCP | **没有这个工具**——agent 只能整读 `index.json` 再自己推 |
| `kbcheck` 的提示 | `R-GRAPH-07` 只在终端打印 17 行「单环节覆盖」 |

最后一条最能说明问题：**这条事实只活到终端关闭为止。** 关掉窗口，17 条路径里
「某个学习成果只讲一次」就重新变成没人知道的事。

更糟的是前两条：`make_tasks` 与（后来才有的）页面如果各写一套过滤条件，
迟早会出现「页面说 37、任务清单说 35」。**两边都「算对了」，只是算的不是同一件事**——
而这种矛盾没有任何检查会发现，因为没有一个地方同时知道两份答案。

## 一条判据：什么算「缺口」

**只收机器数得出来的。** 机器数不出来的——论证站不站得住、前置是否真实必需、
教法在真实课堂有没有效、两个来源是否独立——一律不进来，另列一页
（`docs/GAPS.md` 的「机器不算的那一半」）。

理由不是谦虚，是**防止这张表比实际更权威**：把「人判」混进「机器算」，
读者会以为所有行都是同等确定的事实。

## 改成什么

| 层 | 是什么 |
|---|---|
| 计算 | [`tools/gaps.py`](../../tools/gaps.py) 的 `compute()`——**唯一**算缺口的地方 |
| 呈现 1 | `tools/make_tasks.py`（人读 + `--json` + `--gh` 建 Issue） |
| 呈现 2 | `docs/GAPS.md` / `docs/GAPS.en.md` 的生成块（`--write-index` 写入） |
| 呈现 3 | MCP `scholia_gaps`（默认只回数量，加 `group=` 才列条目） |
| 呈现 4 | `kbcheck` 把同一份 `compute()` 的结果交给页面渲染 |

九个组，每组都写明「为什么算缺口」与「下一步怎么做」：

| key | 数量（2026-10-30） | 判据 |
|---|---|---|
| `review` 三分钟复核 | **570** | `待审` + 有论证 + 证据都读到了 `摘要`/`全文` |
| `review-blocked` 复核前置 | **3** | `待审` 但证据只到 `仅定位`/`未核验`，或论证还没写、没引用证据 |
| `translate` 补译本 | 0 | 没有 `path_en` |
| `methods` 缺教法 | **37** | 知识点没有任何 `教法` 挂上去 |
| `external` 库外前置 | **2** | 同一 `标识` 出现在 ≥2 个对象 |
| `path-thin` 单环节覆盖 | **17** | 成果只被一个环节覆盖（`R-GRAPH-07`） |
| `path-shallow` 证据薄覆盖 | 0 | 覆盖条目的证据最高只到 `仅定位`/`未核验` |
| `todo` 待补 | **110** | 正文里作者自己写了 `**待补**：` |
| `coverage` 覆盖度 🔴 | **2** | 对照人教版目录，整章没有知识点 |

> **别把数量相加**：同一个对象可能同时出现在几行里（一条待审的知识点可以既缺教法、又写着待补）。
> 页面上这句话是加粗的，因为「把九行加起来」听起来像一个可以做完的数字，而它不是。

## 顺带写进索引的两件事

`index.json` 的 `schema_version` 从 4 升到 5，只加字段、不改旧字段：

1. **`覆盖度`**（仅路径）：`已覆盖` / `声明` / `单环节成果` / `证据薄成果`。
   在此之前，这三个数字只存在于 `kbcheck` 的终端提示里。`gaps.compute()` 还会把全库汇总成
   `统计.路径成果`（17 条路径 · 73 个成果 · 67 个只讲一次），所以 README 里那句「92%」现在有生成物可核。
2. **`title_en`**：英文页面与英文检索要能**用英文叫出这条**，而不是把中文标题塞给英文读者。
   没有译本时这个字段不存在——**宁可没有，也不编一个英文名**。

## 顺带修掉的一个错

`llms.txt` 原来手写「`index.json` ≈14k / `citations.json` ≈18k / `evidence.json` ≈9k tokens」。
条目涨到 746 之后，真实值是 **96k / 158k / 38k**——**教人省 token 的那一段，把成本少报了一个数量级**。
更糟的是它跟着建议「一次会话最多整读 `index.json` 一次」：96k 的「读一次」不是省，是奢侈。

现在这张表也是生成块（`render_machine_files_block`），随内容重算；
那条建议改成了「三份都不要整读，查一条用 `scholia_search`」。
这正是本库那条规矩的现场例子：**不写死会漂移的数字**——写了，就会在没人看的时候漂走。

## 代价（不粉饰）

1. **`compute()` 要读文件，不只是读索引。** 它要扫 `methods/*.md` 的 `knowledge_point`、
   正文里的 `**待补**`、覆盖度页的 🔴 行。所以它比「纯 JSON 计算」慢（约 0.3 秒），
   也更依赖目录结构——目录一改，缺口数可能悄悄变。`selftest` 只能保证**页面与计算一致**，
   不能保证**计算的口径仍然正确**；后者仍要人看。
2. **页面上每组只列前 10 条。** 一张 570 行的页面没人读，但「只列 10 条」会让人以为只有 10 条。
   所以每组的截断行都写明「还有 N 项」，并指向完整 JSON。
3. **570 不是「570 × 3 分钟」的工期。** 三分钟的前提是复核者懂这个学科；
   不懂的人要先去读证据。这个数字量的是**排队长度**，不是**剩余工时**。

## 没做的

- **缺口不是错误。** 它不参与 `kbcheck` 的退出码。把缺口设成失败，会逼人为了 CI 变绿而写内容——
  正好是反的。
- **没有历史趋势。** 没有快照，就没有「这个月补了多少」。要趋势得先存每日统计，那是另一件事。
- **排序只按下游依赖数。** 它回答「改它影响多少条别的条目」，不回答「哪条更重要」。
  重要性仍要人判。
