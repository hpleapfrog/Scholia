# 机器入口拆成三份文件：导航 / 引用材料 / 证据

> **English → [three-machine-files.en.md](three-machine-files.en.md)**

> 定于 **2026-10-18**。规则本身见 `llms.txt` 的「机器入口」一节；这里记**为什么**。

## 原来的样子

`index.json` 一份装全部：`objects`（含 `来源`、`适用`、`条件`、`论证`）、
`证据索引`（75 条）、统计、`known_limits`。**179 KB ≈ 48k tokens。**

而 `llms.txt` 写着：**「唯一需要解析的文件是 index.json」**。

于是默认用法变成：**只想问「有没有这条」，却要先吃下全部定位与全部证据。**

## 三个尺寸上的事实

| 事实 | 数字 |
|---|---|
| 一个对象的完整记录里，`来源`（已解析定位）占 | **19.7%** |
| `证据索引` 单独占 | **23%** |
| `scholia_search` 默认回 20 条、每条带来源/适用/条件 | 一次检索 ≈ **6k tokens**——**比读一条正文还贵** |

最后一条最能说明问题：**检索接口比被检索的对象更重，那它就不是检索。**

## 改成什么

| 文件 | 装什么 | 什么时候读 | 体积 |
|---|---|---|---|
| `index.json` | 导航 + **能不能引用** | 每次先读 | ≈14k |
| `citations.json` | 引用材料：`来源` / `证据` / `适用` / `条件` / 免责块 | **按 id 取一条**（≈160 tokens） | ≈18k |
| `evidence.json` | 证据登记（等级 · 核验深度 · 定位 · 许可 · 是否作废） | 核出处时 | ≈9k |

同时在 MCP 侧改了两处：
`scholia_search` 只回导航字段、默认 5 条（≈150 tokens）；
新增 `scholia_cite`，按 id 取一条引用材料。

## 代价（不粉饰）

1. **总字节变大了**：179 KB → 246 KB。因为 `citations.json` 重复了 `id` 之外的少量信息，
   且三份各自带 `$comment`。**这是有意的**：省 token 靠的是「不读」，不是「总和更小」。
2. **要多记一个文件**：引用一条需要两步（先 index、再 citations）。对**不引用**的调用这是净赚，
   对**每条都要引用**的批处理任务反而是多一次查询。
3. **分成紧凑 JSON（无缩进）**：三份都是生成物、从不手改，缩进会让 `index.json` 多出 25% 体积。
   代价是 diff 不可读——但没人靠 diff 读索引，要读有 `START.md`。

## 没做的

- **`evidence/README.md` 与 `evidence.json` 仍是同一份事实的两处**（前者手写、后者生成）。
  真正合一需要把 `evidence/README.md` 改成生成物，那是另一件事。
- **`index.json` 仍可整读**（14k）。对「枚举全库」这是必要成本；
  对「查一条」应走 `scholia_search`（≈150 tokens）。
