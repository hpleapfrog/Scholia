# 溯源档：为什么要在 `status` 之外再加一把尺子

> 2026-11-05。起因不是设计，是一次**读数事故**。

## 一、坏消息先说：这个库最要紧的那个数字，谁也读不出来

跑一遍 `python tools/kbcheck.py`，README 的现状表会告诉你两件事：

```
已确证 / Confirmed      0
待审 / pending review   573
```

两句话都是真的，但它们合起来会被读成一句假话：**「这个库没人核过」。**

2026-11-05 我做了一次全库核算，把每条对象引用的证据按 `核验深度` 取**最弱一环**：

| 读到了哪一层 | 条数 | 占比 |
|---|---:|---:|
| `全文`（引用的每一份都通读过） | 733 | 98.3% |
| `摘要` | 5 | 0.7% |
| `仅定位`（只核了「这一页有没有这段」） | 8 | 1.1% |
| `未核验` / 无据 | 0 | 0 |

**746 条里 738 条（99%）的来源被读到过全文或摘要。** 这个数字一直存在，
只是**没有一个地方显示它**——`status` 那一栏装的是「有没有站得住的论证」，
它要人判，而人只有一个。

于是这个库长期在做一件自损的事：**把最强的证据（读完了）藏起来，只报最弱的结论（没人复核）。**

## 二、为什么不是第七种 `status`

最省事的做法是加一个 `status: 来源已核`。**不行**，理由和当初拒绝「投票定真伪」是同一条：

- `status` 是**真值档**：它回答「这条主张现在站不站得住」。这必须由人给，
  而且 `已确证` 明确要求**非作者**复核（`R-SCHEMA-19`）。
- 「来源读过」是**可核性档**：它回答「顺着这条能不能一路核到底」。这是**机器算得出来的**。

把两件事塞进一个字段，会让机器算出来的东西看起来像人的判断——
这正是本库最反对的那种混淆（见 [status-zero-is-auditable.md](status-zero-is-auditable.md)）。
所以它是**并列的第二把尺子**，叫 `溯源档`，进 `index.json` 与 `citations.json`，
**不进 front-matter**（手写的派生值会漂，而这一维的全部意义是它是对的）。

## 三、为什么取「最弱一环」

三种口径都试过：

| 口径 | 结果 | 问题 |
|---|---|---|
| 取**最强**那条 | 733 条满分 | 一条论证引了 5 份来源、4 份读完、1 份只核了位置，它仍报满分——读者顺着最薄那份核下去会撞墙 |
| 取**平均** | 全库 3.9/4 | 同上，只是把撞墙的概率摊平到看不见 |
| 取**最弱** | 733 / 5 / 8 | 与读者的实际体验一致：**链的强度等于最薄那一环** |

这和 `R-GRAPH-06` 是同一条思路的另一半：那边说「同一来源重复 42 次不构成 42 份证据」，
这边说「5 份来源里读完 4 份不构成读完」。

## 四、边界：它不替任何人背书

- **T4 ≠ 说得对。** 它只说来源被读了，不说结论成立。攻击、复核、`已确证` 一概不经它。
- **T2 ≠ 造假。** 「只核了位置」是**诚实的记录**，不是指控——很多条目只需要确认
  「这一页确实这么写」。
- **它不能靠改字段拿到。** 改不了：它是从 `evidence/README.md` 的 `核验深度` 现算的，
  而 `核验深度` 只有读过的人才写得出来（`M-11` 的来源三问仍然要人答）。

## 五、代价

| 项 | 变化 |
|---|---|
| `index.json` | `schema_version` 5 → 6，每条对象多一个 `溯源`（4 字节） |
| `citations.json` | `schema_version` 2 → 3，引用材料里多一个 `溯源` |
| `docs/GAPS.md` | 多一组「溯源档没到 T4 的条目」，列出**是哪条证据**拖低的 |
| 规则 | **一条没加**。它是派生值，`R-INDEX-01/02` 已经保证它不会过期 |

**没有新增人工负担**，这是它能留下来的原因。

## 六、它对「这个项目还有没有意义」意味着什么

2026-11-05 的实况：1 star · 0 fork · 1 位贡献者 · **0 条已确证** ·
「双语一条 5 分钟」的目标实测 12–13 分钟（[entry-cost-phases.md](entry-cost-phases.md)）。

按「条目数」看，这个项目在输：录入速度追不上缺口，复核队列 570 条只会更长。

按「可核性」看，它手里有一件别处没有的东西：**746 条内容，99% 的来源被逐份读过，
且每一份都记着读到了哪一层。** 这不是「又一个知识库」，是**一套可核对的引用契约**。
它也解释了为什么 `已确证 = 0` 不是失败：**唯一缺的那一环是人，而不是核读。**

所以结论不是「继续堆条目」，是两件事：

1. **把已经有的变成别人能用的**：515 条教科书勘误导成一张表（`exports/errata.csv`），
   教师与教材编辑不需要 Git、不需要读规范就能用。
2. **让陌生人 60 秒内看懂**：一页生成式站点（`tools/build_site.py`），
   把 `status` 与 `溯源` 并排放在每一条上——**两把尺子必须同时可见，缺一个就会误导。**

**衡量这个项目该不该继续的指标，不是第 747 条，是第一个非作者。**
在那之前，任何「再加一个学科」「再补 300 条勘误」都是把问题往后推。
