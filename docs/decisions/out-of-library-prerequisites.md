## 三个选项的评估（Issue #17 原文编号）

| 选项 | 内容 | 评估 |
|---|---|---|
| **1** | 引入 `外部先修`（自由文本字段），与 `edges.先修` 分开 | **推荐。** 最小改动；可机检「**是否声明过**」而不假装管内容；七例可直接迁入 |
| 2 | 新增对象类型「能力」，与 `知识点` 并列 | **成本大于收益。** 一旦成为对象，就要配 `依据` `论证` 与双语——而「会读几何的角」的来源在**物理教材的 `[BL]` 提示里**，为它建节点等于把采集目标换成数学教材 |
| 3 | 承认这就是备注，只写在正文里 | **已经在做的事**，问题是它**不可查询**：上面七例是靠人工 grep 找出来的，下一个人不会知道有七例 |

选项 1 的机械部分其实很窄，值得写清楚它能管什么、不能管什么：

```
能管：声明了 外部先修 却没写学段/来源 → 报错
     某条目的 外部先修 反复出现同一个名称（如「角」出现 ≥2 次）→ 提示「该考虑建节点」
不能管：这条前置是不是真的、该不该前置——仍是判断，进 M-03 那一类
```

**「反复出现 ⇒ 提示建节点」这一条正好命中本节的七例**：「角」会触发 4 次，「矢量」会触发 2 次。

## 为什么仍然没有动 schema

- **schema 改动要单独评审**（本库约束：结构 / 格式变更需另行批准，不与内容批次混提交）。
  本轮只把**例数、原话、选项评估与机械可管范围**摆出来，作为那次评审的输入。
- **动 schema 会让 674 个对象全部重跑校验**，并把 7 条正文改写成字段——
  这是**结构改动**，不是内容补全；混在一起提交会让评审看不出改了什么。
- 若获批准，落地顺序建议：先加**可选字段** `外部先修`（只校验格式，不强制），
  把七例迁入，再谈「进阶 / 后续」是否成为第四类边。

> [!IMPORTANT]
> **本轮没有解决未决 3，只是把它从「只有 1 例、先挂着」推进到「7 例、判据齐了、等一次评审」。**
> 这两个状态的区别不是进度百分比，是**能不能做决定**：
> 前者做决定等于猜，后者做决定有依据。
