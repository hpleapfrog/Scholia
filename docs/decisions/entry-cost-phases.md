# 录入成本分段实测：4 分钟到的是中文正文，超出的是双语与登记

> 未决项见 [README](../../README.md)「未决（要紧的几条）」第 1 条。
> 工具见 [`tools/new_entry.py`](../../tools/new_entry.py) 与 [templates](../../templates/README.md)。记录于 2026-10-20。

「一条条目能不能压到 5 分钟以内」**决定项目生死**——超过这个数，采集速度就追不上
需要覆盖的内容量。**门槛单位已由作者定下：双语一条**（2026-10-20，见下面第二条结论末尾的说明），
因此两次试测的读数分别是门槛的约 **2.4 倍**与**至多 2.6 倍**——后者是墙钟，含一次
**未单独打点的会话中断**（见下面的数据与备注）。两次都**未达标**，但第二次能说出**超在哪一段**。
第一次试测（[速度—时间图的面积等于位移](../../knowledge/physics/claims/速度—时间图的面积等于位移.md)，
ev-151）只留下一个总数：约 12 分钟，**没分段**，所以它只能说明「超了」，不能说明**超在哪**。
第二次试测（[HTTP 451 因法律要求拒绝访问且不暗示资源存在与否](../../knowledge/computing/claims/HTTP451因法律要求拒绝访问且不暗示资源存在与否.md)，
ev-153）按阶段打了时间戳，本节是它的分段结果。

## 分段数据（2026-10-20 · 代理计时）

| 阶段 | 做什么 | 用时 |
|---|---|---|
| P1→P2 | 选题 + 取来源（`rfc9110.txt`） | **3 s** |
| P2 | 在来源里检索本题 | **90 s** |
| P2→P3 | **发现 451 不在 RFC 9110** ⇒ 改找 RFC 7725 并下载 | **1 s** |
| P3→P4 | 取得后读完 §1–§7（283 行 / 9,309 字节） | **17 s** |
| P4→P5 | 比对库里已有条目 + 生成骨架（`new_entry.py`） | **32 s**（骨架本身 **319 ms**） |
| P5→P6 | 定位各小节要写什么 | **57 s** |
| P6→P7 | **写中文正文**（陈述 · 依据 · 论证 A1/A2 · 变更记录） | **49 s** |
| — | **小计：选题 → 中文正文写完** | **249 s ≈ 4 分 9 秒** |
| P7→P9 | 证据登记（中英各一行 + SHA-256 复算）、英文译本、学科索引行、条数订正 | **547 s**（含一次会话中断） |
| P9→P10 | `--write-index` + `kbcheck` 复核 | **929 s**（这一段实际被本节的撰写与自测占用，**不等于校验耗时**） |

**校验本身只要 2.2 秒**（`python tools/kbcheck.py` 全量实测，674 个对象 / 1444 份文档）。
所以「P9→P10」那九百多秒**不能**记在校验头上——这也是分段计时比总数诚实的地方：
12 分钟的总数里，**没有任何一段**知道自己是「写作」还是「等机器」。

**原始打点可核对**：[`entry-cost-phases.tsv`](entry-cost-phases.tsv)（本目录，epoch 为 Unix 秒；
P7 之后会话中断过一次，已在该行的备注里写明——**所以 13 分 16 秒含中断，是上界，不是纯工作量**；
`P8` 与 `P9` 的时间戳相同，也说明这两段不是实时打点）。

## 三条结论，方向各不相同

**一、工具链确实不是瓶颈。** 骨架 319 ms，占全程不到千分之一。第一次试测的这句话被复现了。

**二、真正压破 5 分钟的不是「读与写」，是「双语 + 登记 + 索引」。**
中文正文在 4 分 9 秒时已经写完；**双语一条墙钟 13 分 16 秒**——按墙钟算是门槛的**至多 2.6 倍**。
其中 P7→P9 的 547 秒**含一次会话中断**，中断占了多少没有单独记，**纯工作量的倍数因此没有被测出来**。
超出的部分几乎全花在**平行结构**上：
证据表要在 `evidence/README.md` 与 `README.en.md` **各写一行**，英文译本要**整篇重写一遍**，
学科 README 的索引行与「二十七条」这类计数要跟着改，最后 `--write-index` 重生成三份机器文件。

> [!IMPORTANT]
> **这不是「双语是负担」的意思。** 双语是本库的承重结构，不是包装纸——
> 英文页不是译文，它是同一论证的第二个可核对入口（见
> [英文文件名由 id 派生](english-filenames-from-id.md)）。
>
> **单位问题已由作者定下（2026-10-20）：「5 分钟」= 双语一条。**
> 于是这条未决项从「没法比」变成**有量化缺口，但缺口只测到上界**：双语一条墙钟 **13 分 16 秒**，
> 按墙钟算是门槛的**至多 2.6 倍**，**至多要省 8 分 16 秒**（第一次试测的约 12 分钟约 **2.4 倍**）。
> **为什么只是上界**：P7→P9 那 547 秒里含一次会话中断，完成时刻是补记的，**中断占了多少没有单独打点**。
> **「中文正文 4 分 9 秒」不再是「达标」**——按墙钟它只占双语一条的**前 31%**；
> 按已定单位，剩余部分才是那 8 分 16 秒的出处，而这一段**尚未按子阶段拆开测过**。

**三、代理计时不能当人类计时用，而且差在要害上。**
上表「读完 283 行原文 = 17 秒」对代理成立，对**人**不成立。
人类录入里最贵的一步恰恰是 P3→P4（核读）与 P6（写作），而这两步在代理计时里被压成了几十秒。
**所以「4 分 9 秒」这个数字对人类完全没有参考价值**——它只证明了一件事：
**成本的下界不在工具链，在内容本身**。人类计时**仍未测**，这条未决项没关闭。

## 一个反向的警告：别把检索阶段压掉

P2 那 90 秒里出了本次唯一的**新发现**：`grep -a` 数 RFC 9110 的 §15.5，子节止于 `15.5.22 426`，
全文检索 "451" 命中 **0 次**——451 根本不在 RFC 9110 里（它来自 RFC 7725，经 IANA 注册表收录）。

这条发现直接变成了条目里的 **A2 论证**（「只读 RFC 9110 得不到 451」）。
**也就是说：把录入压到 5 分钟的手段如果是「照抄来源、跳过核对」，压掉的正是产生论证的那一步。**
本库对来源核验深度的要求（`全文 / 摘要 / 仅定位 / 未核验` 四档，见
[evidence/README.md](../../evidence/README.md)）不是为了慢，是为了**只有读过的才能写成主张**。

> [!WARNING]
> **「压到 5 分钟」不是一个无条件的好目标。**
> 一个 5 分钟录进来、依据只有「仅定位」的条目，比一个 12 分钟录进来、全文读过的条目**更便宜也更没用**。
> 该压的是**平行结构的手工成本**（双语行、索引行、计数、机器文件），
> 而不是核读与论证。前者可以交给脚本，后者一交出去，条目就退化成转录。
> **本库后续复核了这句话的前半**：「前者可以交给脚本」**只对 5 个学科的索引行成立**，
> 见下面「复盘『哪一段可以脚本化』」一节。

**本次试测里就出了一次这样的近失。** 中文正文写完时，条目「依据」表里的 RFC 7725 标题是
凭记忆写的《An HTTP Status Code for Indicating Denials of Access Based on Legal Requests》——
**看着比真标题更像那份文档的名字，但它不是原文标题**。
订正它靠的不是重读，而是**P7 的证据登记**：登记行要求写下载文件的头部与哈希，
一比对就露了。**该条目的变更记录里有这一行订正**（中英两份都写了）。

> 也就是说：**慢的那一步（登记可复算的定位）正是抓住错的这一步。**
> 如果为了压时间跳过登记，这条错标题就会以「已核读全文」的姿态留在库里。

## 复盘「哪一段可以脚本化」：P7→P9 不是纯结构抄写

上面把 P7→P9 判成「平行结构的手工成本，可以交给脚本」。本轮动笔前把**登记目标的表头**
全数了一遍，**这个判断只对一半**——学科索引行里有的列**是内容，不是格式**：

| 表头形状 | 出现处 | 能否从 front-matter 抄出 |
|---|---|---|
| `\| 条目 \| 类型 \| 状态 \| 来源 \|` | computing · economics · law · life · transport（5 个学科） | **能**：`type` / `status` / `evidence` |
| `\| 条目 \| 状态 \| 来源 \|` | mathematics · physics(claims) | **能** |
| `\| 条目 \| 类型 \| 状态 \| 证据等级 \|` | medicine | **不能**：`证据等级` 是**证据的属性**，条目 front-matter 里没有这一列 |
| `\| 条目 \| 状态 \| 位置 \| 错误类型 \|` | geography · science（勘误表） | **不能**：`位置`（页/节）与`错误类型`是**从来源读出来的判断** |
| `\| 条目 \| 状态 \| 目标 \| 自检 \|` | physics(路径) | **不能**：`目标`与`自检`是**正文小节的内容** |
| `\| 条目 \| 状态 \| 类型 \| 归属知识点 \| 许可 \|` | physics(教法) | **一半**：`knowledge_point` 可抄，`许可`指**来源**的许可，不在条目里 |
| `\| 条目 \| 状态 \| 针对人群 \| \`禁忌\`（对谁不适用） \|` | physics(误解) | **不能**：`禁忌`是这条误解**最有价值的部分**，脚本写不出来 |

学科 README 的索引表共 **7 种表头形状**，physics 一个学科里就占 4 种。**「化学科索引行」其实是「实现 7 种形状，
其中 4 种要往里填内容」**——那已经不是抄写，是第二次撰写。

证据登记表同理：`evidence/README.md` 有 **3 个** `编号\|类别\|等级\|核验深度\|定位\|时间\|许可\|引用处` 表块
（按批次分开），**选哪个块是人的判断**，而`定位`那一列是**手写的核读记录**——
本次抓住 RFC 7725 错标题的正是这一列。**把它脚本化等于把「可复算的定位」换成占位符。**

> [!IMPORTANT]
> **所以「P7→P9 = 547 秒纯抄写」这个前提被削弱了。**
> 真正无争议可脚本化的是三件事：`--write-index` 的三个机器文件、
> 5 个「类型\|状态\|来源」形状学科 README 的**行存在性**（已有 `R-README-01/02` 守着，缺的只是自动补行），
> 以及**条数句的核对**（脚本数一边，人改另一边——`kbcheck` 已做这件事，成本是 2.2 秒）。
> **本轮没有实现这个脚本**：把一个只对一半的假设写成工具，比不写更贵。

> [!CAUTION]
> **按已定的双语口径，5 分钟这个数字与「双语承重」是相互冲突的两条要求。**
> 门槛 300 秒，而**只写完中文正文就用了 249 秒**——留给「英文正文 + 两份登记 + 索引」的总预算因此是
> **51 秒**；这一段墙钟 **547 秒（含一次中断）**，**至多**是它的 **10.7 倍**。
> 把上面那三件「无争议可脚本化」的事全做到零成本，也省不掉**英文页要按同一论证重写一遍**这一步——
> 而英文页在本库不是译装，是第二个可核对入口（见
> [英文文件名由 id 派生](english-filenames-from-id.md)）。
>
> **所以这不是「再压一压就到」的量级问题，而是要三选一的结构问题**：
> ① 改英文页的**生成方式**（脚本出结构骨架 + 人只核论证与定位，等于承认双语成本可以被工具压掉大半）；
> ② 把门槛退回**单语言口径**（本记录上面那条说明即作废）；
> ③ 保持现状，**承认双语一条 > 5 分钟**，并据此改「采集速度追得上内容量」的那个推算。
> **这是作者的裁决，不是本轮能替作者做的决定。**
