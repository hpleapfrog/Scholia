# 去中心化的教科书与知识库 · 抽象设计

> 状态：抽象设计稿（未实现）
> 范围：协议与数据抽象、判定机制、投影机制、治理与路线图
> 不包含：任何产品代码

---

## 0. 一句话定义

**它不是"一个大家共同编辑的维基"，而是：一张没有任何权威主副本的知识图，任何人都能为它写出属于自己的那本教科书。**

知识图回答 **「什么被谁在什么范围内认领、依据什么、被谁反驳」**；
教科书是这张图**针对某个具体读者**的一次投影。

协议层只负责三件事：

> 这份内容是谁署名的？它从哪里来？它和谁冲突？

协议层**永不回答**"什么是真的"。真伪由每个读者在本地视图里裁决。

## 1. 五条设计公理

| # | 公理 | 推论 |
|---|---|---|
| A1 | 协议不存"正确"，只存「谁、在什么范围、针对什么位置、认领了什么修正」 | 内容寻址 + 署名 + 适用范围是三个必备字段 |
| A2 | **知识要收敛，教法要并存** | 命题有唯一结论；教法禁止排唯一最优 |
| A3 | 索引可重建，视图不权威 | 删光索引仍能完整读出知识；排序永远是本地策略 |
| A4 | 规则即代码，立法与执行分离 | 执行合并的人不能修改规则；规则写在 CI 里 |
| A5 | 可退出 | 任何人可带全部历史分叉，且分叉后不丢失任何东西 |

A2 与 A4 是这套设计最容易被破坏的两条。一旦有人给教法排名，或让维护者绕过 CI，整个系统就退回成中心化权威，只是换了个壳。

## 2. 不变量（直接作为验收标准）

| # | 不变量 | 检验方法 |
|---|---|---|
| I1 | 寻址即校验：标识相同 ⇒ 字节相同 | 重新哈希比对 |
| I2 | 因果可见：任何写入必须引用已知的头 | 无父引用的写入被拒 |
| I3 | 合并良好：幂等、可交换、可结合 | 随机分区重放，结果一致 |
| I4 | 索引可重建 | 删光索引后全量重建，内容等价 |
| I5 | 离线可验证 | 断网状态下验证署名、授权、证据定位 |
| I6 | 无单点权威 | 任意一个节点消失，只减少副本数 |
| I7 | 非墙钟排序 | 顺序仅由因果关系决定，时间戳只作提示 |
| I8 | 分歧显式保留 | 冲突不被静默覆盖，必须是可查询的边 |
| I9 | **结论可复算** | 任何第三方用同一规则，能从同一张图算出同一结论 |
| I10 | 可退出 | fork 后历史完整，无任何能力被单方收回 |

I9 是"公正"的技术定义：不是多数同意，而是**任何人重跑一遍都得到同样结果**。

## 3. 分层抽象

| 层 | 职责 | 可替换实现 |
|---|---|---|
| **L0 传输与发现** | 找到对端、交换字节 | DHT、局域广播、HTTP 镜像、U 盘/二维码 |
| **L1 完整性** | 内容寻址的 Merkle-DAG，父引用即对子树的承诺 | SHA-256 / BLAKE3 |
| **L2 复制与一致性** | 集合同步、反熵、字段级 CRDT | 观察删除集、LWW、RGA |
| **L3 语义** | 四类知识对象 + schema（**schema 自身也是被版本化的内容**） | JSON-LD 兼容，多版本共存 |
| **L4 信任** | 签名、可离线验证的能力令牌链、声誉（校准度）、争议记录 | UCAN 风格委派 |
| **L5 视图与投影** | 论证求值、条件索引、画像投影、本地检索 | 全部可重建 |
| **L6 治理** | 规则即代码、领域维护者、资助、分叉退出 | 非必需层 |

**L1–L4 是协议**（最小、稳定、不许随便加东西）；**L5–L6 是策略**（可替换、可争议）。越"聪明"的东西越不能进协议。

## 4. 知识对象模型

### 4.1 四类对象

| 类型 | 例子 | 判定方式 | 冲突形态 | 是否需要收敛 |
|---|---|---|---|---|
| **命题 claim** | 「V = I × R」 | 真 / 假，按证据等级 | 互斥 | **必须收敛** |
| **教法 method** | 「用『水管』类比讲电流」 | **在条件下**有效 | 并存、互补 | **禁止收敛** |
| **路径 path** | 「先讲极限，跳过 ε-δ」 | 目标达成度 + 先修约束 | 可并列 | 按目标排序 |
| **误解 misconception** | 「把电压当成水流速度」 | 出现频率 + 干预效果 | 互补 | 不收敛 |
| **资源 resource** | 动画、例题、习题集 | 归属 + 可用性 | 版本关系 | 不收敛 |

### 4.2 统一信封

四类对象在协议层是**同一种东西**，只是 `type` 与 `body` 不同。所以引擎只有一个。

```yaml
id:          <内容寻址标识>          # canonical JSON 的哈希
type:        claim | method | path | misconception | resource
author:      <DID>                   # 署名，不可匿名
signature:   <签名>
created:     <ISO 时间>              # 仅提示，不参与排序
scope:                               # 适用范围（A1 的第三根支柱）
  knowledge: [<知识点 id>]
  domain:    物理
  stage:     初中 | 高中 | 本科 | 继续教育
  audience:  <画像特征或人群描述>
  context:   { class_size, device, language, ... }
evidence:    [<证据引用>]            # 每条含类型、等级、可核验定位
body:        <类型专属内容>
edges:
  requires:    [<id>]                # 先修
  supports:    [<id>]
  attacks:     [<id>]
  exemplifies: [<id>]
  diagnoses:   [<id>]
status:      草案 | 待审 | 争议 | 暂定确认 | 已确证 | 已推翻 | 需复审 | 已失效
provenance:  { source: <底本定位>, derived_from: [<id>] }
license:     <授权与再分发条款>
```

### 4.3 教法对象的专用字段

```yaml
body:
  technique:        做法描述
  conditions:       { prior_level, age, class_size, device, language, culture }
  outcome:          { metric: 后测正确率 | 迁移测验 | 留存率, effect_size, n }
  contraindications: [ ... ]        # 对谁不适用 —— 必须有这个字段
```

`contraindications` 是教法领域的"勘误"。它记录的是**这个方法会在谁身上翻车**，例如：

> 水管类比 → 对物理系本科生**不适用**：先修过高，类比反而固化错误直觉。

**方法没有对错，只有对谁、在什么条件下。** 这是 A2 的具体含义。

## 5. 两种判定模式

```
命题 / 路径  →  收敛模式：接地语义求值 → 已确证 | 争议
教法 / 误解 / 资源 → 并存模式：按条件索引 → 对谁有效 | 对谁不适用 | 证据多强
```

### 5.1 论证引擎

讨论不是评论流，是一张图。

```
Argument {
  id, claim,                      # 这个论证要证明什么
  grounds[],                      # 前提，必须可核验
  evidence[],                     # 带等级与定位
  inference,                      # 从 grounds 到 claim 的推理步骤
  attacks[], supports[],          # 指向其他 Argument
  author, status
}
```

**四种有效攻击**（必须机械可检）：

1. **前提不实** —— grounds 中某条事实不成立
2. **推理无效** —— 从 grounds 到 claim 有逻辑断层
3. **证据不足** —— 证据等级撑不起结论
4. **提出更强反证** —— 更高等级、且指向同一 claim

**举证责任刻意不对称**：主张方必须举证；反驳方只需指出一处致命漏洞即算有效。可反驳性优先于可确证性。

### 5.2 结论是算出来的

用 **接地语义（grounded semantics）**：从"没有任何未被击倒的攻击者"的论证开始向外扩张。

它有三个正好需要的性质：**解唯一、保守（宁留争议也不强判）、多项式时间可算**。

于是：

- 存活集合中所有论证结论一致 → **已确证**
- 存活集合中存在结论冲突 → **争议**，并列展示双方最强论证，不选边
- 全程**没有一次投票**

`争议` 不是失败状态。真实世界的深水区本来就是长期争议，强判才是错误。

### 5.3 状态机

```
草案 → 待审 → ┬→ 已确证 ──┐
              └→ 争议 ────┼→ 需复审 → (回到 待审)
                          │
              任何状态 ───┴→ 已推翻 | 已失效
```

- **需复审**：新证据 / 新指南 / 条件变化触发，由定时任务自动降级
- **已失效**：锚点无法重新定位（底本改动导致勘误指不到目标）——进入待审，绝不静默丢弃

## 6. 证据模型

### 6.1 门槛

**讨论可以随便说，但只有过门槛的东西进入论证图、才参与判定。**

必须提供可核验定位：DOI / ISBN+版次+页码 / 官方指南条款 / 公开数据集 ID / 可复算的脚本与数据。未过门槛的留言留在评论区，**不影响结论**。

这一条直接杀死"靠刷帖数量取胜"。

### 6.2 两类证据等级

| 断言类型 | 等级阶梯 |
|---|---|
| 命题 | 系统综述 / 元分析 > 随机对照 > 队列 > 病例 > 专家意见 > **教材本身** |
| 教法 | 可复现的课堂实验 > 准实验 > 大样本课堂数据 > 单一课堂经验 > 专家直觉 |

两点必须承认：

- **教材在命题的证据金字塔里排名很低**，但学生把它当最高权威。这正是本项目存在的理由。
- **单一课堂经验在教法里是合法证据**，因为教法条件性强、迁移性差。把医学的标准直接套到教学上，会把有效的本土经验全部滤掉。

### 6.3 冲突与失效

- 冲突不消灭，记录为显式的 `attacks` 边
- 每条证据带 `as_of`，条件变化（学段、设备、人群）即触发复审
- 反证出现时，旧结论降级而非删除——**为什么错本身是知识**

## 7. 读者画像与投影

### 7.1 画像

```yaml
profile:
  prior:                  { 已掌握知识点: [...], 缺口: [...] }
  goal:                   中考物理及格 | 通过执业考试 | 理解概念 | ...
  constraints:            { time_per_session, total_time, device, language }
  known_misconceptions:   [<misconception id>]
  assessment_history:     [<测评记录>]      # 敏感个人信息，见 §10
```

**画像本身也是内容**：可署名、可分享、可被别人替换。换个画像，同一张图就是另一个人的教科书。

### 7.2 投影

```
project(知识图, 画像, 投影规则) → 教科书
  chapters: [{ 知识点, 绑定教法, 配套资源, 预计时长 }]
  skipped:  [{ 知识点, 原因 }]        # 先修不满足 | 教法不适用 | 目标不需要
```

同一个知识点，两个画像得到两本完全不同的书：

| 画像 A（没学过微积分 · 中考） | 画像 B（物理系本科生） |
|---|---|
| 三章全部用「水管类比」 | 直接从麦克斯韦方程推导 |
| 跳过「场论推导」——先修不满足 | 跳过「水管类比」——该画像下已标注不适用 |

**没有唯一的教科书，只有对某个人的投影。** 这就是"去中心化教科书"的准确含义。

### 7.3 先修关系从哪来（关键落地问题）

先修关系如果全靠人工标注，系统会死在录入量上。三个来源，按优先级：

1. **结构抽取**（自动）：从教材目录、术语定义顺序、公式依赖自动抽取候选先修边。AI 做，人工抽检。
2. **学习数据**（自动）：用实际表现反推——学过 X 再学 Y 与直接学 Y 的通过率差异。这是最硬的证据。
3. **人工标注**（最低）：作为争议时的补充证据。

**关键设计**：先修关系本身是**命题**，不是配置项。

> 「学导数必须先学极限」这句话本身可以被反驳、被攻击、被判为争议。

把课程编排也纳入论证引擎，于是"怎么教"从行政规定变成**可争辩的知识**。

### 7.4 可机械校验的部分（不靠投票）

| 校验项 | 说明 |
|---|---|
| **先修缺口** | 路径里存在"没学就上"的知识点 |
| **循环依赖** | A 是 B 的先修，B 又是 A 的先修 |
| **目标覆盖度** | 画像的目标，内容是否覆盖到位 |
| **禁忌冲突** | 该教法在此画像条件下被标注为不适用 |
| **符号 / 单位一致性** | 全库统一性检查 |
| **引用真实性** | 引用的文献/条款/页码是否真实存在 |

**这是整个系统最该先落地的一段**——它不需要任何人投票，纯程序可判，争议最小。

## 8. AI 的边界

| AI 可以做 | AI 绝对不可以 |
|---|---|
| 抽取：从目录与正文切出候选知识点与先修边 | 成为最终裁决者 |
| 结构化：把 300 条讨论压成一张论证图 | 匿名投票、伪造署名 |
| 检索：找出被忽略的反证 | 生成无来源的"事实" |
| 核算：单位/量纲、数值复算、引用核对 | 计入最高证据等级 |
| **红队：主动构造最强反驳** | 决定谁对 |
| 翻译、查重、总结长讨论 | |

**红队最值钱**：每个主张提出后，AI 必须尝试把它打掉，打不掉的才进入评审。这大幅提高灌水成本。

每条 AI 输出必须署名（模型 + 版本 + 提示），并且**只作为一条证据参与**，永不计入最高等级。

## 9. 治理与去中心化的准确含义

### 9.1 规则即代码

CI 校验器是这套机制的真正实现：

> 存在未被击倒的存活反驳 → **禁止**标记「已确证」
> 存在结论冲突的存活论证 → **强制**标记「争议」
> 存在先修缺口或循环依赖 → **禁止**发布该路径

规则写在代码里，**维护者也绕不过去**。这是公理 A4 的具体形态。

### 9.2 收敛器（未决）

三种权力结构，待定：

| 方案 | 内容 | 代价 |
|---|---|---|
| **A 纯规则** | 机器人按论证语义自动合并，人只在规则失效时介入 | 最公正；冷门知识点会长期悬置 |
| **B 规则 + 领域编辑** | 规则算候选，编辑只能在规则允许范围内签发 | 折中；需严格限制编辑权限 |
| **C 规则 + 轮值裁决** | 裁决权随机轮值、可被申诉推翻 | 防长期把持；流程更重 |

### 9.3 平台可替换

Git 的对象模型天生满足需求：内容寻址、不可变历史、签名提交、分叉即权利。

| 机制 | Git 对应物 |
|---|---|
| 勘误提议 | Pull Request |
| 公开讨论 | Issue（**按论证结构组织**，不是平铺评论） |
| 署名认领 | Review / 签名提交 |
| 冻结版本 | tag（"2027 春季版"） |
| 身份 | 提交签名 |
| 分叉退出 | fork |

GitHub **只是可替换的界面**。只要所有人能 clone 到完整历史，封号、封锁、涨价都不会让知识消失。缺的四样（结构化投票、证据等级、AI 规模化、时效状态机）由 repo 内的结构化文件 + CI 补齐。

### 9.4 声誉 = 校准度

不用抽象的 PageRank。**声誉 = 你历史上认领的判断，后来被多少独立证据支持或推翻。** 这是可被事实检验的预测记录，不是人气。

## 10. 法律与伦理红线

| 红线 | 措施 |
|---|---|
| **版权** | **绝不上传教材全文或扫描页。** 只存页码定位、短引用、原创摘要与结论。事实与数据不受版权保护，**表达**受保护 |
| **学情数据是敏感个人信息** | 画像默认本地存储、加密、可加密擦除；上传必须显式同意且可匿名化 |
| **医疗 / 教育建议** | 明确免责；严格区分"知识勘误"与"医疗建议""教学处方" |
| **诽谤风险** | 措辞克制；只陈述可核验的事实；结论可溯源到证据 |
| **认知锁定（双刃性）** | 勘误必须自洽可验证、导读可自建、**裸读模式永远可用** |

最后一条要特别强调：这套机制也能被用来**制造**依赖——故意留错、只在内部给勘误。所以抽象里必须内置三条解药：**勘误可独立验证、导读可自建、可退出**。

**防自学永远是一层可选择的覆盖，不是一把锁。** 这个系统真正的价值是「修正的透明与可追溯」，不是「制造信息不对称」。

## 11. 失败模式与对策

| 失败模式 | 对策 |
|---|---|
| 水军 / 多数暴政 | 无投票；论证语义 + 证据门槛 + 校准度权重 |
| 靠量取胜（消耗战） | 论证图去重、有限；AI 合并同义论点；堆量无效 |
| 冷启动没人参与 | 机器人先产出**可机械校验**的候选清单，让首批审核零成本 |
| 大众在专业领域系统性错误 | 证据等级优先于人数；领域权重 |
| 长讨论腐化 | 原子化（一个 thread 一个可判定 claim）+ 结论先行 + 时间盒 |
| 无限拖延 | 反驳有有效期，逾期未补强自动失效（致命错误例外） |
| AI 幻觉污染 | AI 输出必须附可核验来源，永不作为裁决依据 |
| 平台封锁 | Git 对象层去中心化 + 多平台镜像 |
| 永争议不收敛 | **允许**。长期挂「争议」，并列双方最强论证，允许双版本并存 |

## 12. 路线图

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| **M0 只读镜像** | 单本**开源**教材 → 知识点切分 + 机械校验错误清单 | 抽取出 ≥200 条知识点；机械可验证的错误清单可复算；**不下任何"对错"结论** |
| **M1 论证引擎** | 命题收敛模式上线，单学科跑通 | 接地语义求值可复算；CI 能阻止"有存活反驳却标记已确证"；至少产出 1 条真实的「争议」 |
| **M2 并存 + 投影** | 教法并存模式 + 画像投影 | 同一张图对两个画像生成两本不同的教科书；先修缺口与禁忌冲突可自动检出 |
| **M3 去中心化** | 多节点复制、镜像、fork、退出 | 节点全灭只剩一份 clone，仍能完整重建并重算出全部结论 |

**试点建议：不要从医学起步。** 医学验证最依赖专家、法律风险最高、错误代价最大。第一站选**对错可被程序判定**的科目——数学（证明/计算）、计算机（代码/复杂度）、物理（量纲/数值）。这些科目的勘误可以自动化验证，几周内就能跑通完整闭环。

**理想的初始数据集**：找一本**已经公开勘误表**的教材。出版社的官方勘误表就是现成的标准答案，能直接用来校准抽取与判定，衡量系统准确率。
